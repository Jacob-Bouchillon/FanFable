# Handoff — relationship accuracy

**Date:** 2026-10-29
**Branch:** `experiment/evidence-scan`
**Purpose:** everything a new session needs to continue the one problem this branch exists for — getting true relationships out of a book into the bank, with evidence, without banking scenes.

---

## 1. Where it stands

| measure | value |
|---|---|
| bank rows (trial book) | 164 relations: 23 `user_confirmed`, 1 `accepted`, 122 `provisional`, 18 `needs_review` |
| review queue | 258 tie notes: 133 sweep proposals, 120 unsupported, 5 open-vocab |
| judge precision (42 blind-labelled rows) | **0.83** counting reinforcement, 0.78 establishment-only |
| judge recall | **0.68** counting reinforcement, 0.70 establishment-only |
| judge stability | 6 of 42 verdicts flip across identical runs (14%) |
| extraction, 9B | 91 relations and 48 facts in 31 of 66 windows (partial run) |

The single most important result: **the code was never the thing rejecting relationships — the labels were.** The old gold standard said a family title ("Aunt Petunia") proved nothing; five of the model's "false positives" were correct under the standard the product actually wants.

## 2. The judge

Model: **`gpt-oss:20b` with `think: "low"`** (see §5 — without it the model returns nothing). Prompt variants measured on the same 42 rows:

| variant | precision | recall |
|---|---:|---:|
| boolean "does it establish a lasting relationship" | 0.72 | 0.65 |
| **three categories: establishes / reinforces / mentions / none** | **0.78** (0.83 incl. reinforces) | 0.70 (0.68) |
| passage-bounded ("judge only this passage") | 0.71 | 0.50 |

The categories prompt is the current best. It is in `testing/trials/claim-confidence/judge-variants.ts` under `categories`.

**Error profile — two concrete defects, both fixable in the prompt:**

1. **Identity.** `Plagueis — partner — "The Muun"` and `Palpatine — colleague of — Sidious` are the same person twice. The judge treated alias pairs as two people.
2. **Titles.** Seven of the seven misses are family titles — "Aunt Petunia", "Uncle Vernon", "Great Auntie Enid" — which the judge refuses as "present but no relationship".

## 3. The labels

Three categories, because the old binary conflated them:

- **establishes** — the passage itself supplies the evidence.
- **reinforces** — the relationship is presupposed ("their partnership", "his wife").
- **mentions** — both appear, no relationship stated.

Distribution on the 42: 20 establishes, 2 reinforces, 16 mentions, 4 unclear.

Files: `testing/trials/adjudication/gold-three-way-sheet.md` (blind sheet), `gold-three-way-key.json`, `gold-three-way-labels.tsv`.

**Known label defects.** Four "unclear" verdicts reasoned from outside knowledge ("The Muun is Plagueis", "Sidious is Palpatine") despite instructions not to. Two rows involve the word "bill" as an invoice matched to a character named Bill.

## 4. What the code does now

- `canPromote` is reduced to mechanical checks: distinct entities, quote verbatim, anchor verbatim, citation honesty (a sub-span may not hide a hedge), and a **confidence threshold** (default 0.7, project setting `minConfidence`).
- The assertion matcher, `KIN_GROUPS`, the synonym lists and the `open-vocab` gate are **deleted**. The concept set remains for labelling and querying only.
- The model returns an assessment (`names_both`, `asserted`, `other_person`, `directness`, `strength`, `why`) stored in `supporting_evidence`; `strength` drives the tier.
- `lore assess` scores existing rows in place (dry run by default).
- `lore sweep` fills the review queue from per-character ledgers.
- `lore relationships` and `lore proposals` are the read views.

## 5. The model trap that cost three hours

`gpt-oss:20b` is a reasoning model. Ollama puts its deliberation in `thinking`, and those tokens count against `num_predict`.

- At 2,048 and at 8,192 output tokens it produced **0 characters of content** with `done_reason: "length"` (29,546 characters of thinking at 8k). The extractor parsed nothing and logged `empty-answer` for all 66 windows.
- `think: false` is **silently ignored** by this build.
- `think: "low"` works: 456 characters of thinking, 4,480 characters of correct JSON.
- `llm.ts` now accepts `think?: boolean | 'low' | 'medium' | 'high'` and passes it through.

## 6. Traps and lessons (all of these cost time)

1. **Never launch a full run without a one-window smoke.** A 66-window run was wasted because a model was tested only on short prompts.
2. **Killing the shell does not kill the child.** `stop` on a background command left `lore extract` running for 23 minutes and competing with a second run for the GPU. Always `ps` afterwards.
3. **Reasoning models share their budget with the answer.** Check `done_reason` and `thinking` length before concluding a model "returned nothing".
4. **Labels are a hypothesis.** Score against re-read labels, not the first pass. Five "false positives" were correct.
5. **Match the metric to the prompt.** A variant that predicts `reinforces` must have `reinforces` counted as positive, or it scores its own correct answers as errors.
6. **The 226-row gold key lost row identity** for 184 rows — only `gold-map.json` kept `relId`. Any new labelling must store the relation id on every row.
7. **Two extraction processes on one GPU thrash the model** and both crawl.
8. **Don't run extraction when the question is about judging.** It produced nothing relevant and burned an hour.

## 7. Next steps, ranked

1. **One prompt variant** adding two rules to the categories prompt: two names for one person are not a relationship; a title or form of address establishes what it names. Measure on the 42. Expected: the 3 identity false positives and most of the 7 title misses move.
2. **Stability**: majority of three runs of the winner. 14% flip is the remaining noise floor.
3. **Apply the winner** to the candidate pairs and produce the relationship list — the actual deliverable for the planner.
4. **Re-label a random sample of a whole book**, storing `relId` for every row, so accuracy is known beyond these 42 hard cases.

```bash

# judge variants (42 rows, gpt-oss:20b, think low)
node --experimental-strip-types testing/trials/claim-confidence/judge-variants.ts categories

# blind re-read
node --experimental-strip-types testing/trials/claim-confidence/blind-gold.ts out.json

# extraction, one window first, always
cp testing/trials/model-ab/hp3.db /tmp/opencode/smoke.db
node --experimental-strip-types … # reset lore_mined for one window, then:
npm run fanfable -- --db /tmp/opencode/smoke.db --project ab lore extract --model qwen3.5:9b --max-windows 1
```

Ollama must be running; `qwen3.5:9b` and `gpt-oss:20b` are both installed.
